\section{Overview}

Path Message Passing (PMP), the search procedure underlying Isolating Path Effects (IPE),
scores a candidate path extension by actually running the model with that path's message
substituted. Path Attribution Patching (PAP) replaces this measurement with a first-order
gradient approximation, trading exactness for the cost of a backward pass reused across all
candidates at a level. This experiment quantifies that trade: how much time and memory the
approximation saves, and how much circuit quality it costs.

Three search modalities are compared under an identical grid of discovery hyperparameters:

\begin{description}
  \item[PMP] Path Message Passing. Each candidate extension is scored by an isolated forward
    evaluation of the path it would create. This is the reference method.
  \item[PAP] Path Attribution Patching. Candidate contributions are approximated by the inner
    product of the candidate's message with the gradient of the metric at the attachment point,
    so one backward pass scores every candidate at a level.
  \item[PMP-b] PMP with batched expansion: an attention block is evaluated whole and only the
    surviving blocks are split into individual heads (and, positionally, into token positions).
    PAP has no analogue of this optimisation, so PMP-b is reported as the practical PMP baseline
    while PMP is the strict algorithmic-parity comparison.
\end{description}

\section{Implementation}

\subsection{Search grid}

Each modality is run over 6 discovery configurations spanning three
admission strategies from coarse to fine:

\begin{description}
  \item[Threshold] admit any extension whose contribution exceeds $\tau$ in absolute value,
    with $\tau \in \{0.5,\ 0.1,\ 0.02\}$. Note that $\tau$ lives on the scale of the
    \texttt{logit\_difference} metric and is therefore \emph{not} comparable across models.
  \item[Best-first] a global priority queue over candidate extensions, expanded until $n$
    complete paths have been found, with $n = 100$.
  \item[Beam] breadth-first expansion retaining the top $w$ candidates per level, with
    $w \in \{100,\ 1000\}$.
\end{description}

Crossing these 6 configurations with the three modalities and with positional
and non-positional search gives 36 cells per model. In positional mode every
model component is additionally split per token position, so a single expansion enumerates
$n_\text{components} \times \text{seq\_len}$ candidates rather than $n_\text{components}$.

A note on one omission. The grid originally also carried a best-first configuration at
$n = 1000$. Best-first maintains an \emph{unbounded} priority queue --- unlike Beam, which
caps it at $w$ per level --- and positionally the queue of live candidate objects exhausted
system RAM before 1000 complete paths could be found. That configuration was removed from the
grid for all models rather than reported for some and not others; its cached records remain on
disk but are excluded from every table here.

The task is Indirect Object Identification, drawn from the \texttt{mib-bench/ioi} dataset.
Samples are bucketed by tokenised length and a single length is chosen per tokenizer rather
than fixed in advance, since the right value differs between the two tokenizers; both models
resolved to length 16. Only samples whose indirect object and subject are
single tokens are retained, because the logit-difference metric indexes them directly, and the
counterfactual prompt must tokenise to the same length.

The search scores on 5 prompts; circuit evaluation uses a \emph{disjoint} slice of
64 prompts from the same length bucket. The search metric is the IOI logit difference
under counterfactual denoising, with the \texttt{s2\_io\_flip} counterfactual as the clean
signal patched into the corrupted run.

\subsection{Circuit evaluation}

A discovered path set is converted to a circuit by taking the union of its nodes and edges.
Faithfulness is measured by knockout: the model is run with every component outside the circuit
mean-ablated, the ablation values being the mean of an ABC-counterfactual run accumulated over
minibatches. The resulting logit difference $F(C)$ is normalised against the full and empty
circuits of the same model,
\[
  \widehat{F}(C) \;=\; \frac{F(C) - F(\varnothing)}{F(M) - F(\varnothing)},
\]
so that $\widehat{F} = 1$ reproduces the full model and $\widehat{F} = 0$ is no better than
ablating everything. The two normalising constants are measured once per model and reused, so
scoring one circuit costs a single pass over the evaluation set. All faithfulness figures
reported below are $\widehat{F}$.

\subsection{Measurement protocol}

Each cell is timed around the search call alone, excluding model loading, data preparation and
scoring, all of which are shared across cells. GPU memory is reported as
\texttt{torch.cuda.max\_memory\_allocated} after a \texttt{reset\_peak\_memory\_stats} and cache
flush immediately before the search, so the figure is the device-wide peak during that search.

Every search runs under a wall-clock budget of one hour. A search that reaches the budget
returns the paths found so far and is flagged; such cells are marked $\dagger$ throughout, and
their times are \emph{censored at 3600\,s} rather than measured. This matters for interpreting
the ratios in Table~\ref{tab:speedup}: wherever PMP times out, the reported speedup of PAP over
PMP is a lower bound, often a severe one.

Experiments ran on a single NVIDIA RTX 4090 (24\,GB) with 62\,GiB of host RAM. Each model's
grid runs in one subprocess so the weights are loaded once, and every cell is cached to its own
file, making the sweep resumable after an interruption without recomputing completed work.

\section{Findings}

\paragraph{PAP is one to two orders of magnitude faster than PMP.}
Against strict algorithmic parity the median paired speedup is $22.6\times$ on GPT-2 small
non-positionally and $52.6\times$ positionally. Against batched PMP --- the honest practical
baseline, since batching is an optimisation PAP cannot use --- the advantage narrows to roughly
$5\times$ on both models non-positionally. The gap widens with positional granularity, which is
where the candidate set grows by a factor of the sequence length.

\paragraph{The gradient approximation costs real circuit quality at small and medium sizes.}
At matched circuit size on GPT-2 small, PMP reaches $\widehat{F} = 0.937$ in the 15--35\% band
where PAP manages only $0.019$; in the 35--70\% band the two close to $0.926$ against $0.896$.
By the 70--101\% band they are indistinguishable. The pattern is that PAP's first-order
approximation misranks candidates when the circuit is sparse and the interactions it linearises
away still matter, and stops mattering once the circuit is nearly the whole model. On
Llama-3.2-1B the ordering partly reverses --- PAP leads in the 5--15\% band, $0.308$ against
$0.149$ --- but PMP's figures there are depressed by timeouts rather than by search quality.

\paragraph{PAP does not save memory.}
Peak GPU memory is consistently \emph{higher} for PAP than for either PMP variant: 959\,MB
against 831\,MB on GPT-2 small non-positionally, and 7544\,MB against 6938\,MB on
Llama-3.2-1B. The retained gradient graph costs more than the avoided forward evaluations save.
The saving PAP offers is in time, not in space.

\paragraph{Plain PMP does not converge positionally at 1B scale.}
Five of six positional PMP cells on Llama-3.2-1B hit the one-hour budget, and the block's best
faithfulness is $0.119$. Batched PMP recovers most of the ground ($0.920$ with one timeout) and
PAP recovers all of it ($1.005$, no timeouts). Positional search on a billion-parameter model is
where the batching optimisation, and the gradient approximation, stop being conveniences and
become necessary.

\paragraph{The headline trade.}
PAP buys a large constant-factor speedup --- roughly $5\times$ over a well-implemented PMP, far
more over a naive one --- at the cost of a genuine quality drop in the sparse-circuit regime
that most interpretability work cares about, and with no memory saving. Where PMP converges, it
produces better circuits; where it does not, PAP is the only method of the three that finishes.

\section*{Caveats}

\begin{itemize}
  \item Times for cells marked $\dagger$ are censored at the one-hour budget, not measured.
    Nine of Llama-3.2-1B's 36 cells and two of GPT-2 small's are affected, concentrated
    almost entirely in the PMP blocks, so every PMP time and every PMP/PAP ratio involving them
    understates the true gap.
  \item Threshold values are on the metric's own scale and are not comparable across models;
    the matched-size comparison in Table~\ref{tab:matched} exists precisely to avoid reading
    across a shared hyperparameter.
  \item Each cell is a single run. No variance estimate is available, and the timing figures
    include whatever contention the host was under.
  \item Faithfulness is measured by mean ablation against an ABC counterfactual. Conclusions
    about circuit quality are conditional on that ablation choice.
  \item Both models are reported at one search batch size (5 prompts) and one evaluation
    set size (64 prompts). Sensitivity to either was not measured.
\end{itemize}
